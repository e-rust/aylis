Como o aylis funciona por dentro

O aylis é um framework de interface em Rust. Os componentes descendem de um ancestral comum, o layout usa align, anchors, margins e padding, os eventos se ligam por nome, os forms são JSON editados numa IDE feita com o próprio aylis e os dados ficam num ClientDataSet. O código do app pode ser em Rust, Python, TypeScript, C#, Java, Go, C++ ou Pascal.

Cada parte abaixo tem um diagrama. Use Avançar para seguir passo a passo, Repetir para voltar ao começo e Tocar para ver tudo sozinho. Os nomes são os do código.

Componentes e a árvore

O Ui guarda todos os componentes numa arena. Cada um é uma struct que implementa o trait Component e é achado por um ComponentId, um índice com geração: depois de liberado, o id antigo não aponta para mais nada.

O caminho de um clique

Do botão do mouse até os pixels novos na tela: a plataforma entrega o evento ao Ui, o Ui acha o controle, dispara o evento, o handler chama set_prop, a mudança marca o layout e a pintura sai pelo Canvas do renderizador.

O ciclo de layout

Quando algo muda, o Ui marca layout_dirty. No próximo update_layout, o realign percorre a árvore de cima para baixo: para cada contêiner, os filhos encaixados consomem a área livre e o que sobra vai para o client. Parte 7

  
As linguagens

  
Num projeto, o visual (forms, temas, assets) é um só e o código fica numa pasta por linguagem
  (rust/, python/, typescript/...). Rust roda no mesmo processo da tela. As outras rodam um
  backend que conversa com o aylis-host pelo protocolo JSON do aylis-remote, uma mensagem por linha. Quem
  tem FFI também pode usar a C ABI (aylis-capi), no mesmo processo.
